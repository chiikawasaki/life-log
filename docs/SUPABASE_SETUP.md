# Supabaseの接続と初期化

## 現状

開発環境には `VITE_SUPABASE_URL` と `VITE_SUPABASE_PUBLISHABLE_KEY` が設定済み。認証設定APIはHTTP 200を返しています。
2026-11-17に管理API経由でマイグレーションを適用しました。5テーブルすべてでRLSを有効化し、匿名の読み取りが拒否されることを確認済みです。
一般サインアップは無効化済みです。管理画面のAdd userでのユーザー作成は可能です。
2026-11-17、作成された1件のメール確認済みユーザーを所有者に登録し、初期6ステータスを作成しました。既存プロジェクトにマイグレーションを再実行する必要はありません。
`DATABASE_URL` のTCP接続は切断されましたが、`SUPABASE_ACCESS_TOKEN` を使うHTTPS管理APIで接続できています。
キー・パスワードはチャットやGitに貼らないでください。

## 新しいプロジェクトを初期化する場合

1. Supabase Dashboardで対象プロジェクトを開き、SQL Editorへ移動します。
2. 既存のアプリ用テーブルがないことを確認し、`supabase/migrations/202611160001_mvp.sql` の内容を実行します。トランザクションでまとめて適用されます。適用済みのSQLを重ねて実行しないでください。
3. AuthenticationのUsersから自分用のユーザーをメール・パスワードで作成します（メールを確認済みにする設定がある場合は、自分のアドレスであることを確認して使用）。パスワードをチャットに送る必要はありません。
4. Users画面でそのユーザーのUUIDを確認し、SQL Editorで次を実行します。

```sql
-- <所有者ユーザーのUUID> を Users 画面の実際の値に置換する。
insert into public.app_owner (user_id)
values ('<所有者ユーザーのUUID>'::uuid);
```

5. Authenticationの設定で新規サインアップを無効にします。アプリ内には新規登録画面がなく、DBも `app_owner` の1ユーザーだけを許可しています。
6. 開発サーバーを起動し、登録したメールとパスワードでログインします。初期6ステータスは初回ログイン後に作成されます。
7. 行動ルールを登録し、記録→訂正→削除を確認します。スマホとPCで同じアカウントにログインし、再読み込み後に同じ記録が表示されることを確認します。

## 開発担当にDB適用を任せる場合

SupabaseのConnect画面からSession poolerの接続文字列（IPv4対応）を確認し、秘密情報を含む値は開発環境の環境変数 `DATABASE_URL` に安全に設定してください。
DB接続ではTLS証明書を検証します。必要ならSupabaseの接続設定から取得したCA証明書も環境に配置します。
所有者のユーザー作成はダッシュボードで行い、ユーザーUUIDを共有するか環境変数 `APP_OWNER_USER_ID` に設定できます（UUIDはパスワードではありません）。
現在のプロジェクトでは管理APIによるDB適用が完了しています。所有者登録と実DBロールでの読み書き確認も完了しています。画面からのパスワードログインと端末間同期は別途確認します。

## リリース前

実プロジェクトでの認証・記録・同期を確認するまで、セットアップ完了とは扱いません。
公開する場合はホスティング先とアクセス方法を別途決めます。現時点でアプリのデプロイは行っていません。
